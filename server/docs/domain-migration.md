# Смена публичного домена SOMS!

Текущий адрес: `https://soms.angelfish-leaffish.ts.net`.
Tailscale Funnel направляет HTTPS на `http://127.0.0.1:8000`, где работает nginx.

Смена `SERVER_URL` не переписывает абсолютные ссылки, уже сохранённые в MySQL.
В частности, `/users/{id}/avatar` отвечает перенаправлением на `avatar_url` из базы.
Успешного ответа JSON профиля недостаточно: нужно скачать саму картинку с переходом по перенаправлению.

## Порядок переноса

1. Сохранить копии `server/.env`, `launcher/launcher.json`, `launcher/shared-launcher.json`,
   `switcher/SomsSwitcher.cs` и опубликованного `server/static/client/SOMS-switcher.exe`.
   Копии с секретами хранить вне `static`.
2. Задать имя устройства и сети Tailscale. Проверить фактический DNSName через `tailscale status --json`.
3. Заменить прежний hostname в четырёх конфигурационных файлах. Сохранить пути сервисов и хеши модулей клиента.
4. Пересоздать `app` с новым окружением и перезапустить nginx. Использовать существующие тома
   `server_mysql_data`, `server_redis_data` и `server_spectator_state`.
5. Перенастроить Funnel на новый DNSName, сохранив локальную цель `127.0.0.1:8000`.
6. Пересобрать `switcher/build-switcher.ps1` и скопировать только полученный EXE в `server/static/client`.
7. Выполнить перенос сохранённых ссылок командой ниже. Обязательно проверить результат без записи первым запуском.
8. Проверить действительные файлы, API и ссылки для клиента. Передать игрокам обновлённый свитчер.

## Ссылки в базе и кэше

Утилита `tools/migrate_public_domain.py` получает новый адрес из текущего `SERVER_URL`.
Она обрабатывает аватарки, обложки и значки пользователей, ссылки событий, изображения и сайт команды.
Вложенные JSON-структуры сохраняются; чужие домены и текстовые упоминания не переписываются.
Перед записью проверяются локальные файлы, создаётся резервная копия затронутых полей,
затем изменения применяются одной транзакцией. Пользовательский кэш и кэш рейтинга со старыми ссылками удаляются.
Сессии, очереди, скоры, статистика и файлы не меняются.

Из каталога `server` (утилита включается в образ при сборке):

```powershell
docker compose exec -T app python -m tools.migrate_public_domain --from-url https://OLD_HOST
docker compose exec -T app python -m tools.migrate_public_domain --from-url https://OLD_HOST --apply --backup /app/logs/domain-migration-backup.json
```

Путь резервной копии должен быть новым: существующая копия не перезаписывается.
Повторный запуск после успешной миграции должен показать пустой список изменений.

## Проверка результата

- Внешний HTTPS проверять через IP из публичного DNS с сохранением имени TLS (`curl --resolve`). На компьютере с Tailscale обычный запрос домена может идти через MagicDNS на внутренний адрес `100.x.x.x`, даже если Funnel для друзей не работает.
- `/health`, `/site/`, `/client/manifest.json`: HTTP 200, все адреса manifest используют новый origin.
- Все загруженные аватарки: перейти по `/users/{id}/avatar`, получить изображение и сравнить его байты с локальным файлом.
- Профиль, рейтинг и лента событий: нет ссылок на прежний домен, включая вложенные структуры и кэш.
- Обложки, значки и изображения команд: проверить реальные URL, если такие изображения загружены.
- `SOMS-switcher.exe` и модули клиента: скачанные файлы совпадают с опубликованными SHA-256.
- Скоры, статистика, медали и SOMSAI: сверить число записей и контрольные суммы до/после исправления ссылок.
- Реплеи: отдельно сверить `has_replay` с наличием файла. Этот флаг сам по себе не доказывает, что файл сохранён.
- SignalR: без авторизации ожидается отказ 401; внутренний `/_lio` должен оставаться недоступен снаружи.
