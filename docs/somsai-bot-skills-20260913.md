# SOMSAI: навыки ботов по профилю — 13 сентября 2026

Установлены API, spectator и клиентский модуль для lazer 2026.804.2. Через свитчер нужно обновить клиент и создать новый кастом: профиль навыков фиксируется при создании матча.

## Поведение

- Уровни: «Легко · 6 digit», «Средне · 5 digit», «Сложно · 4 digit», «Топ 1000 · 3–2 digit», «mrekk · всегда FC». Старые запросы `expert` и `impossible` принимаются как `top1000`; числовые значения старого клиентского enum сохранены.
- Ранг влияет непрерывно: начальная оценка комфортной сложности `clamp(11.6 - 1.4 * log10(rank), 2.5, 11)`. Это настраиваемая эвристика, а не статистически откалиброванное соответствие ранга и звёзд.
- Профиль строится по выборке до 16 результатов из топ-100 с охватом разных модов и типов карт, плюс до 8 последних попыток, включая неудачные. Повторы исключаются. История немного корректирует оценку по рангу.
- Сопоставляются сочетание модов, BPM, AR, CS, плотность нот, доля слайдеров, длина, соотношение aim/speed и нагрузка на выносливость. NC сопоставляется с DT, DC — с HT; настройка скорости учитывается в характеристиках карты.
- Для osu! дополнительно разбираются `.osu`: изменения интервалов между объектами, повороты и расстояния, форма/повторы слайдеров и изменения их скорости. Отдельно используется `slider_factor` калькулятора. Эти признаки применяются вместе с модами, в том числе NM, HD, HR, HDHR и DT.
- Название слота NM4/DT2/TB не определяет его тип. Техническая карта и тайбрейкер оцениваются по содержимому; длительность также влияет на усталость.
- Пики выбираются по сильным сторонам команды; баны защищают слабые стороны. Учитывается средняя сила команды и её слабейший участник. Небольшой воспроизводимый разброс разрешает близкие варианты.
- В геймплее используется фактическая сложность с модами из нативного калькулятора. Плотные участки и усталость увеличивают ошибки, а карта заметно ниже уровня бота играется уверенно. Счёт и точность рассчитывает нативный ScoreProcessor. mrekk сохраняет FC.
- Это приближённая модель по выборке результатов. При недоступной истории используется ранг; недоступные технические признаки не считаются нулевым навыком. Движение курсора бота по-прежнему основано на нативном autoplay, модель управляет результатами попаданий.

## Данные и нагрузка

Профили запрашиваются только для выбранных ботов. Кэш истории — 6 часов, пустой истории — 60 секунд, атрибутов — сутки, технических признаков карты с известной контрольной суммой — 14 дней. Максимальный бюджет обогащения — 48 запросов в минуту, из них до 32 на профили; остальное резервируется под пул. Кэш не расходует бюджет.

Создание профиля ограничено 12 секундами и допускает частичные данные. Пул обогащается после создания комнаты, вне блокировки SOMSAI: локальный performance-server рассчитывает модифицированную сложность по точной ревизии `.osu`. Заполнение метаданных не меняет ревизию пользовательского действия. Схема БД не изменена.

Форматы запросов сверены с [документацией osu! API](https://osu.ppy.sh/docs/index.html#get-beatmap-attributes). Признаки `aim_difficulty`, `speed_difficulty` и `slider_factor` доступны в [BeatmapDifficultyAttributes](https://osu.ppy.sh/docs/#beatmapdifficultyattributes).

До выпуска не было активных матчей SOMSAI. Пересозданы только app и spectator; MySQL, Redis, performance-server, nginx и Caddy сохранены. Старые ID работающих контейнеров отсутствовали среди образов Docker, поэтому содержимое доступных образов проверено против работающих контейнеров: все Python-файлы API, main.py, lockfile, зависимости и DLL spectator совпали. Для отката назначить резервные теги основными и выполнить `docker compose -f server/docker-compose.yml up -d --no-deps --no-build --pull never app spectator`, затем восстановить DLL и обе конфигурации из резервной папки. Не удалять orphan-контейнер Caddy.

После готовности API требуется `docker exec friends-private-osu-nginx-1 nginx -s reload`: при пересоздании контейнера меняется его IP, а nginx может сохранять старый адрес. Это было причиной временного 502 во время выпуска. Spectator трижды перезапустился, пока API ещё загружался, затем успешно инициализировал все режимы и остался запущенным.

Сборка API выполнена поверх проверенных прежних зависимостей с заменой семи файлов; опубликованный архив соответствующего серверного исходного кода обновлён. Dockerfile и подготовка контекста сохранены в папке выпуска. Обычный lazer и stable не изменялись.
