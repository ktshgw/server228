# Обрыв публичного HTTPS — 12.09.2026

У друзей сайт возвращал `PR_END_OF_FILE_ERROR`. Локальный `/health` отвечал 200, контейнер приложения был `healthy`. Запрос домена с компьютера сервера также отвечал 200, но шёл на внутренний адрес Tailscale `100.121.134.84`, поэтому не проверял публичный Funnel.

Через Google DNS-over-HTTPS получены публичные адреса домена `soms.angelfish-leaffish.ts.net`: `185.40.234.55`, `185.40.234.75`, `185.40.234.198`. При принудительном подключении к каждому через `curl --resolve` с сохранением имени TLS все три соединения завершались ошибкой handshake до HTTP-ответа. Проверка сертификатов не отключалась.

Локальная конфигурация Funnel уже содержала HTTPS 443, `AllowFunnel: true` и цель `http://127.0.0.1:8000`. Выполнен запрос синхронизации `tailscale debug force-netmap-update`, затем повторная регистрация только существующего входа:

```powershell
tailscale funnel --bg --https=443 off
tailscale funnel --bg --https=443 --yes http://127.0.0.1:8000
```

После этого каждый из трёх публичных IPv4-адресов вернул 200 для `/site/` с успешной проверкой TLS. Через публичный маршрут дополнительно проверены `/health`, `/client/manifest.json` и `/client/SOMS-switcher.exe`: все 200. Конфигурации до/после совпадают; копии находятся в `.test-tmp/funnel-tls-20260912`.

Сбой локализован в публикации/маршрутизации Funnel. Точная внутренняя причина у Tailscale не установлена. Перезапуск службы Windows был недоступен с текущими правами и не выполнялся; повторной регистрации через CLI оказалось достаточно. Серверные контейнеры, домен, сертификаты и пользовательские данные не изменялись.

При следующих проверках внешнего доступа нужно получать адреса из публичного DNS и принудительно подключаться к ним: обычный запрос домена на компьютере с Tailscale может проверить только внутренний маршрут. Пример для одного адреса из текущего публичного DNS:

```powershell
curl.exe --noproxy "*" --resolve soms.angelfish-leaffish.ts.net:443:185.40.234.55 --connect-timeout 8 --max-time 20 -sS -o NUL -w "HTTP=%{http_code} IP=%{remote_ip} TLS=%{ssl_verify_result}" https://soms.angelfish-leaffish.ts.net/site/
```

Адреса Funnel могут меняться: перед повторной проверкой получить актуальные записи A. Публичный IPv6 и подключение непосредственно из сети друзей в этом прогоне не проверялись.
