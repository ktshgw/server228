# Смена аватара на сайте — 12.09.2026

В настройках аккаунта → профиль добавлен блок «Аватар»: текущее изображение, выбор файла, предпросмотр, сохранение, отмена и удаление. На собственной аватарке профиля доступна кнопка «Сменить аватар», открывающая этот раздел. Кнопка скрыта в чужих профилях и для гостей. Текст о правилах не добавлен.

Используется существующая загрузка `POST /api/private/web-site/me/avatar`. Добавлен `DELETE` по тому же адресу для возврата стандартной аватарки. Сервер проверяет сессию, Origin и CSRF. Удаление файла выполняется после успешного коммита и только для пути, принадлежащего текущему пользователю. Сбой очистки уже неиспользуемого файла не выдаётся за неудачное сохранение профиля.

Поддерживаются PNG, JPEG, GIF и WebP до 5 МБ и 2048 × 2048 пикселей. Существующий серверный обработчик обрезает изображение по центру и сохраняет PNG 256 × 256; GIF остаётся без анимации. Ограничения указаны рядом с выбором файла. После изменения обновляются аватарки профиля, шапки и меню пользователя, а также уже показанные карточки этого пользователя. При выходе из аккаунта ожидающая загрузка отменяется.

Проверено:

- 40 серверных тестов `test_web_avatar` + `test_web_site`, включая загрузку/кодирование, возврат стандартного изображения, ограничения доступа, защиту чужих файлов и сохранность прежнего файла при ошибке коммита.
- Ruff для изменённого Python-кода; `node --check` для JavaScript.
- `scripts/check-avatar-browser.mjs`: настоящий Edge, отдельный профиль браузера, мобильный и настольный виды. Проверены предпросмотр, отмена, неверный файл, отказ сервера, multipart/CSRF, обновление всех собственных аватарок, удаление, чужой профиль и выход из аккаунта. Записи перехватываются фикстурой, реальные аккаунты не изменяются.

Исходные файлы сохранены в `.test-tmp/site-avatar-20260912/before`. Предыдущий образ: `soms-server-backup:before-site-avatar-20260912`. Скриншоты находятся в `.test-tmp/site-avatar-20260912/desktop.png` и `mobile.png`.

Изменения опубликованы пересборкой и перезапуском только контейнера `app`. При проверке опубликованной страницы обнаружена блокировка локального предпросмотра политикой CSP: для изображений сайта добавлен источник `blob:`. Разрешения скриптов не изменены. После исправления весь сценарий `node scripts/check-avatar-browser.mjs --deployed` прошёл успешно.

Публичная проверка через внешний IP Funnel с сохранением имени хоста и проверкой TLS подтвердила совпадение SHA256 HTML, JavaScript и CSS с исходниками. Неавторизованный DELETE аватара возвращает 401. `/health` возвращает `status: ok`. Финальный образ приложения: `sha256:84f3a769a9f7f2698961b05313e9bd2c01365a044dda9d5388015f3f06eaa4e6`.
