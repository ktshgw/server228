# Stealth mode в SOMS

Настройки → Debug / Отладка → Stealth → **Stealth mode**.
Сразу под переключателем находится **Reroll stealth**, ниже — состояние подбора,
выбранный ник, отображаемый ранг и сравнение PP.

При первом включении выбирается случайный официальный игрок с близким PP
в текущем режиме. Приоритет у одинакового округлённого PP; при нехватке
кандидатов используется ближайшая окрестность. Игрок сохраняется до
выключения/повторного включения, кнопки Reroll или нового запуска клиента.
Ник и аватар сохраняются при изменении PP и переключении режима игры.
После изменения PP обновляется только отображаемый мировой ранг. Сетевые
ошибки не меняют выбранного игрока; обновление ранга повторяется через 15 секунд.
Запоздавшие ответы после выключения/реролла отбрасываются.

Подмена действует локально на текст и аватары интерфейса, карточки пользователя,
профиль, панель аккаунта и legacy-панели. Настоящие ID, API.LocalUser,
кэш статистики, учётные данные, сохранённые результаты и серверные записи
не перезаписываются. При выключении восстанавливается исходное отображение.
В JSON настроек сохраняется только включённость функции, без выбранной личности.

## Ограничения официальных данных

Официальный API ограничивает общий рейтинг первыми 10 000 игроками:
[RankingController osu!web](https://github.com/ppy/osu-web/blob/master/app/Http/Controllers/RankingController.php).
Для меньшего PP дополнительно используются официальные рейтинги стран,
которые содержат реальные мировые позиции этих игроков. Подбор не является
равномерной выборкой всех аккаунтов osu!; точное совпадение PP не гарантируется.
Первоначально показывается настоящий ранг выбранного игрока. Последующее
движение ранга ниже топ-10 000 оценивается по соседним значениям PP и мировым
позициям. В настройках такая оценка отмечена; прирост PP не может ухудшить
показанный ранг из-за погрешности выборки. Чужая настоящая позиция на osu.ppy.sh
от этого не меняется. Рейтинг страны и график личного ранга скрыты при подмене.

## Исправление запуска (09.09.2026)

В реальном клиенте `1788977640.runtime.log` показал исключение из
`SomsStealthAttachPatch.Postfix`: `Game.AddInternal` намеренно выбрасывает
`InvalidOperationException: Use Add or Content instead`. Поэтому сессия не
создавалась, а настройки оставались на «Ожидание входа в SOMS…».
Предыдущий тест вручную добавлял сессию и не проверял этот путь запуска.

Теперь сессия добавляется через `Game.Add` после `LoadComplete` основного
`LocalUserStatisticsProvider`, который lazer загружает асинхронно. Проверяются
режим SOMS, соответствие провайдера зависимости игры и отсутствие уже
подключённой сессии. Открытие настроек и дополнительные провайдеры не создают
дубликатов.

В `Soms.Stealth.Check` убрано ручное добавление сессии: тест загружает основной
провайдер асинхронно и проверяет реальное автоматическое подключение через
Harmony, включая запуск с сохранённым включённым параметром. Обе проверки
прошли на установленном runtime lazer 2026.804.2, также прошли прежние сценарии
PP/реролла/восстановления отображения. Полная проверка регистрации патчей:
106 уникальных регистраций, 11 успешных проверок, без дубликатов.

Выпуск: `SomsStealthStartupFix`.
SHA-256: `1a61732b9002c09c7e20c9f58785f56f73f0108a350a9872cddec46b2198e1c4`.
Проверены публичный манифест, повторно скачанный DLL и оба пина лаунчеров.
Серверное приложение не пересобиралось. Startup hook и switcher не изменились.
